# Задание для GLM

## Роль и очередь

Реализуй игровой код, не ограничивайся ревью или советами. Начинай только после завершения и коммита задач ChatGPT и Mistral; прочитай их work-отчёты и проверь, что целевые файлы чисты. До этого не редактируй проект.

## Задача — система повторяемых корпоративных событий

Разрешены новые файлы `call_events.py`, `test_call_events.py` и интеграционные изменения `main.py`.

Создай полноценную систему телефонных событий, которая заменит часть однотипных случайных звонков основной игры:

- Реализуй не менее восьми коротких событий с разными корпорациями/персонажами, абсурдной иронией, вариантами ответа и измеримыми последствиями для существующих игровых ресурсов/флагов.
- События должны учитывать уже доступные сюжетные флаги, не повторяться бесконечно и открывать повтор при обоснованном условии (например, следующий игровой день или изменившийся сюжет).
- События и уже увиденные идентификаторы сохраняются в `save.json`; старые сохранения без полей событий продолжают загружаться.
- Вынеси каталог, проверку доступности и выбор события в чистые функции `call_events.py`. Игровые эффекты применяй через явный результат, не используй глобальные переменные в модуле.
- Подключи систему к существующему механизму звонков в `main.py`, сохрани его управление, таймеры и обычные случайные события.
- Добавь тесты каталога, требований по флагам, повторов/сброса и сериализации состояния. Не имитируй прохождение через изменение реального `save.json`.

Не добавляй зависимости, ASCII-арт, комментарии или docstring. Не удаляй существующие звонки, пока новое покрытие не доказывает, что пользовательские варианты сохранены. Если старый механизм невозможно подключить без потери сюжетных веток, остановись и подробно перечисли их в отчёте.

Проверки:

```powershell
python -m unittest -q test_call_events test_vibe_plus
python -m py_compile main.py call_events.py test_call_events.py
```
