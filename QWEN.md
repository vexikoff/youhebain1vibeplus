# Задание для Qwen

## НОВАЯ ЗАДАЧА — большая система достижений для Vibe Plus

Предыдущая работа Qwen по интеграции достижений уже завершена и находится в истории Git. Теперь реализуй отдельное расширение кода. Не ограничивайся ревью, планом или предложениями.

### Очередь и область изменений

Работай только с `achievements.py` и `test_achievements.py`. Не меняй `main.py`, `vibe_plus.py`, `test_vibe_plus.py`, сохранение, зависимости, README или чужие инструкции: интеграция достижений уже подключена к главному циклу и экрану достижений.

Перед началом проверь `git status`, последние коммиты и актуальные версии файлов. `vibe_plus.py` сейчас развивается отдельно; не делай предположений о номерах новых глав. Используй устойчивые поля состояния (`ending`, `route`, `origin_route`, `evidence`, `trust_level`, `side_quest`, `archive_policy`) и нормализуй/безопасно отображай их в контексте достижений. Если какого-то поля нет в старом сохранении, существующие достижения и загрузка должны продолжать работать.

### Что реализовать

Добавь не менее 12 полноценных достижений Vibe Plus, ориентированных на разные решения игрока, а не только на достижение порогов глав:

- разные допустимые политики архива: публикация с согласием, ограниченный доступ, сводка и осознанный отказ от публикации;
- осторожное обращение с доверием и доказательствами, включая сочетания этих показателей;
- завершение побочного дела и дальнейшее использование его материалов;
- разнообразные исходы разбирательства из уже существующих концовок;
- отдельные достижения за маршруты/решения, если их можно надёжно определить из актуального сохранённого состояния.

У каждого достижения должны быть уникальный стабильный `id`, короткое ироничное название и точное описание условия. Не выдавай достижения за недостижимые комбинации и не считай незаполненные/повреждённые поля успешным прохождением. Порог глав не используй как единственный критерий новых достижений: индексы меняются при расширении DLC. Сохрани все существующие ID и поведение достижений; неизвестные ID по-прежнему не должны попадать в нормализованное сохранение.

Обнови версию схемы достижений при необходимости и сохрани миграционную совместимость. Проверь, что unlocked достижение не теряется при следующем `update`, повторное получение идемпотентно, а экран отображает полное новое количество и состояния.

### Тесты, отчёт и коммит

Добавь тесты нормализации новых полей, старых/неполных сохранений, каждого нового условия и отрицательного/повреждённого случая, повторного обновления уже открытых достижений и отображения новых записей. В тестах используй синтетические словари; не читай и не перезаписывай `save.json`.

Запусти:

```powershell
python -m unittest -q test_achievements
python -m py_compile achievements.py test_achievements.py
```

Проверь `git diff --check`. Добавь фактический отчёт в конец `QWEN_WORK.md`, затем создай отдельный коммит только `achievements.py`, `test_achievements.py` и `QWEN_WORK.md` с trailer `Co-authored-by: Copilot <223556219+Copilot@users.noreply.github.com>`. Не делай push без отдельной просьбы владельца.
